# Feeds

A feed is one configured source of observations: a built-in poller such as OpenSky, a JSON API, a byte stream from a receiver or a TAK server, or an external system that sends to Sentinel over TCP or UDP. This page covers the lifecycle of a feed, the management API, configuration and secrets, what each driver does, how several ingest replicas share the work, and what to write to add a driver.

## Lifecycle

```
operator / gateway ──▶ feeds (desired state, Postgres) ──LISTEN/NOTIFY──▶ every ingest replica
                                                                              │ lease: one owner per feed (feed_leases)
                                                                              ▼
                                   driver ──▶ runner (provenance, dedupe, raw bounds) ──▶ observations.raw (protobuf)
                                                                              ▼
                       entity-service: resolve identities ──▶ fuse (newest fix wins) ──▶ entities, observations, entity_sources
                                                                              ▼
                                                     entities.events ──▶ track, alert, search, analytics, gateway WebSocket
```

1. **Desired state** lives in `sentinel.feeds`: id (an immutable slug), name, driver, `config` (validated against the driver's JSON Schema plus the common options), `secret_refs`, `enabled`, `version`. Every write bumps `version` and notifies the replicas.
2. **Ownership.** With leases enabled (the default) each enabled feed runs on exactly one replica. Replicas heartbeat `ingest_replicas`; a feed's preferred owner is chosen by rendezvous hashing over the live replicas, or by `config.pinnedReplica`; a connection that binds a port is placed among the listener replicas only (see Listeners below); the owner holds a `feed_leases` row it renews every `LEASE_TICK_SEC` (2 s) with a `LEASE_TTL_SEC` (15 s) expiry. Acquisition bumps the fencing token, which travels on every observation (`x-fence` header, `fencing_token` field) and guards status writes, so a replica that lost its lease cannot overwrite the new owner's work. A non-preferred replica steps in only after the preferred one had a TTL to claim a free feed, and hands the feed back after `LEASE_REBALANCE_SEC` (30 s) once the preferred replica is live.
3. **Running.** The supervisor builds the driver, wraps it in a runner and starts it. A driver that fails to start or exits with an error is restarted with backoff (`FEED_RETRY_MIN_SEC` to `FEED_RETRY_MAX_SEC`). A version bump restarts the feed with the new configuration.
4. **Observations.** The runner stamps provenance (feed id, driver, receive time, lease token), guarantees an identity (a canonical one such as ICAO24 or MMSI when the decoder found one, else `FEED_LOCAL` over feed id and source entity id), bounds the raw payload (`rawPayload: none|bounded|full`, bounded to `RAW_PAYLOAD_MAX_BYTES`), suppresses a fix that repeats the previous one within a second and ten metres (still forwarding one every 5 s so downstream last-seen times move), computes the deterministic observation id, and publishes to `observations.raw` keyed by identity so one object's reports stay in order. Payloads nothing could decode go to `observations.dlq` (at most `DLQ_RATE_PER_SEC` per feed) with the reason and error in headers.
5. **Status.** The owner writes `feed_status` every 5 s: state (`starting`, `running`, `idle`, `degraded`, `error`, `stopped`), health from the time since the last report against `staleWarnSec` / `staleCriticalSec`, counters, last error, applied version and driver detail (area, credits, connections, lease token). `GET /feeds` from any replica overlays the live status for feeds running there and renders a row whose replica stopped reporting as `unassigned`.
6. **Outbound.** A connection (direction `out` or `both`) also runs a pump beside its driver on the owning replica: its own Kafka consumer group `sentinel-conn-<id>` on `entities.events` (and `alerts.events` unless `policy.alerts.enabled` is false), so offsets survive restarts and handovers and a slow remote never stalls another connection. Each event is checked against `config.policy` (loop and re-export guards first, then classification ceiling, entity type, feed, boxes), coalesced per entity (only the newest snapshot waits; a removal replaces any pending snapshot and is never dropped), spaced by `outbound.perEntityMinSec`, rate-limited by `outbound.maxEventsPerSec`, and handed to the driver. `deleted` and `aged_out` events become removals for entities the remote knows; an entity that stops passing the policy is removed after `outbound.policyExitGraceSec`; events older than `outbound.maxLagSec` are dropped rather than replayed. While the driver reports it is not connected the pump pauses and keeps the queue. `feed_status.detail.outbound` carries `delivered`, `deliveryErrors`, `denied`, `coalesced`, `dropped`, `queueDepth`, `tracked` and `consumerGroup`; `messagesTotal` and `lastSuccessAt` include deliveries. Losing the lease cancels the pump, which leaves the group so the new owner resumes from the committed offset.
6. **Fusion** happens in the entity-service: observations from different feeds that share a canonical identity update one entity, the newest source timestamp wins, rejected fixes are kept as observations with a reject reason, and per-feed ageout thresholds apply. See `docs/data-model.md`.

## Management API

Served by the ingest service on `HTTP_ADDR` (`:4000`) and proxied by the gateway under `/api/v1`. The gateway presents `X-Sentinel-Service-Token` (`INGEST_SERVICE_TOKEN`); reads need any authenticated user, writes need `sentinel-operator` or `sentinel-admin`. The gateway itself may push areas with the bare service token.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/feeds?driver=&enabled=&capability=&direction=` | Every feed with its status (array); `direction=in` or `out` also matches `both`, `direction=both` only `both` |
| POST | `/feeds` | Create: `{ id?, name, description?, driver, config, secretRefs?, enabled? }`; the id is slugified from the name when omitted. 422 with `details[{path,message}]` on validation failure, 409 on a duplicate id |
| GET | `/feeds/{id}` | One feed |
| PUT | `/feeds/{id}` | Replace the mutable fields (`name`, `description`, `config`, `secretRefs`, `enabled`) |
| PATCH | `/feeds/{id}` | Merge patch; `config` merges one level deep, `null` removes a key; `id`, `driver`, `builtin` are immutable |
| DELETE | `/feeds/{id}` | 403 for a built-in feed (disable it instead) |
| POST | `/feeds/{id}/enable`, `/feeds/{id}/disable` | Persisted desired state |
| GET | `/feeds/{id}/status` | The status row (live when the feed runs on the answering replica) |
| GET, PUT | `/feeds/{id}/area` | Area of interest for drivers with the `area` capability: `{ active, clients, boxes[{north,south,east,west}] }`, at most four boxes that never cross the antimeridian; the response adds `live`, `idle`, `areaSqDeg`, `effectiveIntervalSec`, `creditsRemaining`, `lowCredits`, `lastPollAt`, `nextPollInSec`, `expiresAt`. 409 for a driver without the capability |
| GET | `/drivers`, `/drivers/{id}` | The catalog: id, name, description, source, `direction`, capabilities, `configSchema`, `secretFields` |

The feed resource carries `source` (the EntitySource label its observations use), `direction` (`in`, `out` or `both`: the driver's direction, narrowed by `config.direction` when set), `capabilities` (`poll`, `area`, `listen`), `builtin`, `version` and `status`. A feed that sends (`out` or `both`) is a *connection*: it consumes `entities.events` and `alerts.events` under the same lease and status machinery and pushes what its `config.policy` allows to the remote system.

## Configuration and secrets

`config` is validated against the driver's schema (served on `/drivers/{id}`) and the common options every driver accepts:

| Key | Purpose |
|-----|---------|
| `staleWarnSec`, `staleCriticalSec` | Health thresholds (defaults `FEED_STALE_WARN_SEC` 120, `FEED_STALE_CRITICAL_SEC` 300) |
| `backpressure` | `block`, `drop` or `nack` between a transport and its decoder; the transport default applies when absent |
| `pinnedReplica` | Run only on this replica. Optional: a connection that binds a port runs on a listener replica without it, and one that sets it runs on the named replica, listener or not |
| `classification` | Default level (`UNCLASSIFIED`, `CONFIDENTIAL`, `SECRET`, `TOP_SECRET`) stamped on every observation; a decoder may only raise it. Entities keep the highest level any feed reported. Link 16 feeds should set `SECRET`, since the decoder does not read the header's security field |
| `rawPayload` | `none`, `bounded` (default) or `full` raw bytes kept on each observation |
| `direction` | `in`, `out` or `both`; narrows a driver that can do both, never widens one (422 otherwise) |
| `policy` | Sharing policy of an `out` or `both` connection (422 on a driver that only receives): `entityTypes[]`, `feeds[]` (feed ids that must have contributed), `boxes[{north,south,east,west}]` (up to 16; `west > east` wraps the antimeridian), `classificationCeiling` (default `UNCLASSIFIED`), `reexport` (send entities another connection contributed to; a loop back to the same connection is always prevented), `alerts{enabled, minSeverity, types[]}`. Empty lists mean no restriction |
| `outbound` | Sink tuning: `queueMax` (10000), `perEntityMinSec` (5), `maxEventsPerSec` (200), `maxLagSec` (300), `policyExitGraceSec` (30) |

Secrets never appear in `config`. Each driver declares `secretFields`, and `secretRefs` maps them to references the owning replica resolves at start: `env:VARIABLE_NAME` (the variable must be set on every replica) or `file:/absolute/path` (the file's contents, trimmed; how mounted secrets and PEM certificates arrive). Plain values are rejected.

**CelesTrak notes.** CelesTrak has no API keys or accounts; it has a [usage policy](https://celestrak.org/usage-policy.php) instead. Elements update every two hours, the large groups (`active`, `starlink`) allow one download per update per IP and answer a repeat with 403, and more than 50 error responses in two hours from one IP lead to a firewall block. The driver fetches each selection once per refresh with a conditional request (`If-None-Match` / `If-Modified-Since`, so an unchanged file is a 304), honours `Retry-After`, and never refreshes more often than every two hours. On any other error it retries with backoff from 1 s to 60 s, which means a block is retried every minute: watch `status.detail.errors` and `lastStatus` on the feed, and keep selections few (each catalog number is one request). Six-digit catalog numbers (in use since July 2026) are carried in the OMM record; the synthetic two-line elements on each observation use a placeholder in the line's five-column field and the real id beside them. The map propagates satellites between fixes from those elements and draws the selected satellite's orbit (`docs/frontend.md`).

**IntelSky notes.** IntelSky needs no key or account; it throttles per IP (60 requests a minute on the live feed, 200 on `stats/*.php`) and answers 429 past that, without JSON error bodies, and asks commercial or high-volume users to contact it first. The feed has no area filter, so the driver polls the whole of it (about 75 aircraft) six times a minute; failures back off from 1 s to 60 s or honour `Retry-After`, never faster than the interval, and a body that is not JSON (IntelSky serves `text/html` even for JSON) is dead-lettered. `now` is in milliseconds and `dbFlags` is the operator's flag emoji, read as `countryOfOrigin` (`US`, `FR`, …). Aircraft are drawn in the military orange; the gateway's `/api/v1/aircraft/{hex}/path` serves their past paths from IntelSky's track endpoints (`docs/api-gateway.md`). IntelSky replaced adsb.lol: `ADSB_LOL` remains a valid source for old entities and track points, and existing databases drop the old feed with `DELETE FROM sentinel.feeds WHERE id = 'adsb-lol'; DELETE FROM sentinel.feed_ageout_config WHERE "feedId" = 'adsb-lol';`.

**aisstream.io notes.** aisstream.io needs a free account and an API key, and forbids using it from a browser, so only the ingest replica that owns the feed sees it. A connection must subscribe within 3 s of opening and may change its subscription at most once a second. The driver sends the whole subscription on connect, resubscribes only when the boxes change after rounding outward to 0.1° and at most every 2 s, waits 5 s for the `SubscriptionConfirmation` (else it reconnects), pings every 30 s, and reconnects with jittered backoff from 1 s to 60 s; the last failure stays in `detail.connections.<area|watchlist>.lastError` until a subscription is confirmed again. An account may hold three connections and this feed uses up to two, so a second deployment on the same key would hit the limit. The service drops consumers that fall behind and replays nothing: the driver reads into a 10 000-message buffer and counts what it cannot queue (`detail.dropped`) rather than block. It offers permessage-deflate, worthwhile since aisstream.io limits the bandwidth of uncompressed connections (`detail.connections.*.compression`). Messages are go-ais packets as JSON and go through the same mapping as the `nmea-ais` decoder, so vessels from aisstream.io and from a local receiver fuse on MMSI. Volume is modest: about 115 messages a second for the whole world and a few a second for the English Channel (October 2026). While a view is over the cap the map shows counts for aisstream.io vessels only; vessels known only from a receiver are hidden until the view is zoomed in below it.

**TCP and UDP connections.** These drivers are for systems that send to Sentinel instead of being polled. Each datagram of a `udp` connection is one message (JSON, NMEA and SBS may put several lines in one); a `tcp` stream is split by a framing. `format` picks the decoder, `sentinel` by default: the `sentinel.v1.Observation` message (`proto/sentinel/v1/observation.proto`; the Connections page offers the `.proto` files for download). With `encoding: protobuf` a TCP sender writes length-delimited messages (a varint length, then the message: Java `writeDelimitedTo`, Go `protodelim`) and a UDP sender one message per datagram; with `encoding: json` both send the protobuf JSON form, one message per line. The framing a format implies is `delimited` for `sentinel` protobuf, `line` for `sentinel` JSON, `xmlevent` for `cot`, `beast` for `beast` and `line` for the rest (set `framing: lengthprefix` for `link16` over TCP); `framing` overrides it. A message needs `source_entity_id` or an identity, and a position it carries must lie inside WGS84 bounds, else it is dead-lettered as `missing_identity` or `bad_position`; the fields Sentinel owns (feed, replica, fencing token, observation id, raw payload) are ignored whatever the sender wrote. The Connections page shows each connection's endpoint, a test command and Go and Python senders; `GET /feeds/{id}` reports where it listens in `status.detail`: `listen{protocol,host,port}` (or `connect`), `format`, `tls`, `allowlist` (`open` or the entry count), `malformed` (messages the decoder rejected) and, for listeners, the sender table and counters described below.

**Listeners.** A connection that binds a port (`tcp` in listen mode, `udp`, and `stream` with a `tcpserver` or `udp` transport) runs only on a *listener replica*: an ingest replica started with `INGEST_LISTENER=true` that uses the host's network, so any port chosen in Connections is reachable on the host with no port mapping. `INGEST_LISTENER_HOST` is the address senders use (`detail.listen.host`, shown in the send guide; the node address on Kubernetes unless `ingestListener.host` is set). Compose runs it as the `ingest-listener` service of the `inbound` profile (`docker compose --profile inbound up -d ingest-listener`, management API on `127.0.0.1:4010`); Docker Desktop on Mac and Windows needs Settings › Resources › Network › Enable host networking (4.34 and later), Linux needs nothing. The Helm chart runs it as `ingestListener` on a labelled node (`docs/infrastructure.md`). Placement among the live listener replicas follows the usual lease rules; `pinnedReplica` stays optional and, when set, overrides it. While no listener replica is live, an enabled listening connection shows state `unassigned` with the last error `no listener replica (run the ingest listener: INGEST_LISTENER=true)`.

*Port rules.* The management API refuses (422, `details[{path,message}]` on `/config/port`, or `/config/transport/address` for `stream`) a listening port outside 1024-65535 (lower ports need root on the host), a port another listening connection of the same protocol already uses (enabled or not, so enabling both later cannot clash; a TCP and a UDP connection may share a number) and a port Sentinel itself uses. Those are `INGEST_RESERVED_PORTS`, comma-separated ports and ranges, default `3000-3005,4000,4010,4200,5000,5001,5432,8080,8600,9000,9001,9092,9093,9200,9600`; an empty value means the default, and a value replaces it, so repeat what you still want. The replica that answers the request checks it, so set it the same on every ingest replica. A port already taken on the host by something else fails when the connection starts and appears as its last error.

*Protection.* `allow` lists the IPs and CIDRs that may send; an empty list is open to anyone who can reach the port. A sender that is not on it is dropped before any data is read (`rejected`). `maxConnections` caps concurrent TCP connections (`refused`); `maxMessagesPerSec` is shared by all senders of the connection, and what exceeds it is dropped (`rateLimited`); a TCP frame or UDP datagram over `maxMessageBytes` closes the TCP connection or drops the datagram (`oversize`). A TCP connection may stay quiet indefinitely unless `readTimeoutSec` is set: then one that sends nothing for that many seconds is closed. A listener treats that as an ordinary disconnect; in connect mode it is recorded as the last error and Sentinel reconnects. With `tls.enabled` a TCP listener serves `tlsCert` and `tlsKey`; `tls.requireClientCert` makes it mutual TLS, accepting only clients whose certificate chains to `clientCa`. Failed handshakes, and TLS clients on a plain listener, count as `tlsFailed`. In connect mode `serverCa` verifies the remote, `tlsCert` and `tlsKey` present a client certificate and `serverName` names the certificate to expect. Per sender, `detail.senders[{remote,since,lastAt,messages,connected}]` lists the connected ones and those seen in the last 10 minutes (at most 50) and `detail.distinctSenders` counts them; the counters are `accepted`, `rejected`, `refused`, `rateLimited`, `oversize` and `tlsFailed`.

*Security notes.* UDP source addresses can be forged, so a UDP allowlist stops mistakes, not attackers: on a network you do not trust use TCP with mutual TLS and an allowlist. An empty allowlist is open. The listener replica's own management API is guarded only by `INGEST_SERVICE_TOKEN` (`/health` and `/metrics` there are open). Compose binds it to `127.0.0.1:4010`, so it is not reachable from the network; the Helm chart binds `:4010` on every interface of the node for the kubelet probes, so keep `:4010` closed to outside networks there. Change the default `dev-ingest-token` anywhere but a development machine.

Decoders for `stream` (`tcp` and `udp` pick one with `format`):

| Decoder | Input | Source | Notes |
|---------|-------|--------|-------|
| `sentinel` | `sentinel.v1.Observation`, binary protobuf or JSON (`tcp` and `udp` only, `format: sentinel`) | from the message (`defaultSource`) | Server-owned fields ignored; `missing_identity` and `bad_position` dead-lettered |
| `json` | JSON object or array, or a batch document with `records` | `options.source` (UNSPECIFIED) | Field map (`fields.latitude`, `fields.longitude` required; id, name, altitude, speed, heading, course, timestamp, callsign, …), `identityType`, `timeFormat`, `altitudeUnit`, `speedUnit`, `entityType`. The default map is the legacy position shape |
| `sbs` | BaseStation CSV (readsb port 30003) | ADS_B | MSG 2/3 fixes; MSG 1/4/5/6/8 as positionless partial observations |
| `beast` | Mode-S Beast binary (readsb port 30005, `framing: beast`) | ADS_B | Identification, CPR airborne position (global pair within 10 s, then local), velocity, status, Mode S altitude and squawk replies for known aircraft |
| `nmea-ais` | NMEA VDM/VDO (AIS-catcher, receivers) | AIS | Types 1–3, 5, 18, 19, 21, 24, 27; fragments reassembled per sender. A vessel's static and voyage detail (name, IMO, callsign, type, dimensions, destination, ETA, draught) is remembered for a day after its last message and carried on its later reports, since each report replaces the entity's AIS detail |
| `nmea-gps` | NMEA GGA/RMC | GPS | Needs `options.sourceEntityId` (the platform the receiver reports) |
| `cot` | Cursor on Target XML (`framing: xmlevent`) | COT | Affiliation and environment from the type; tasking events skipped |
| `link16` | JREAP-C binary (`framing: lengthprefix`) | LINK16 | J-series track messages |

A frame that carries nothing (a heartbeat, a partial fragment, an unsupported message) is counted as skipped by reason; a frame that fails to decode is dead-lettered; a decoder panic is recovered and dead-lettered.

Backpressure between a transport and its decoder: `tcpclient`, `tcpserver` and `websocket` block (TCP flow control reaches the sender), `udp` drops, `stomp` nacks, `mqtt` blocks up to 2 s then drops. All of it is counted (`frames_dropped_total`, `nacked_total`, `blocked_seconds_total`).

Recipes for readsb, AIS-catcher, a TAK server, a JSON API and external systems sending over TCP or UDP are in `docs/development.md`.

## Replicas and operations

- Environment: `KAFKA_BROKERS`, `KAFKA_OBSERVATION_TOPIC`, `KAFKA_DEADLETTER_TOPIC`, `DATABASE_URL`, `HTTP_ADDR`, `INGEST_SERVICE_TOKEN` (required in production), `INGEST_LISTENER` (`true` makes the replica take listening connections), `INGEST_LISTENER_HOST` (the address senders use), `INGEST_RESERVED_PORTS` (ports a listening connection may not take; blank is the default list), `REPLICA_ID` (hostname; the pod name in Kubernetes), `FEEDS_BOOTSTRAP_ENABLED` (built-ins inserted enabled on first start), `PUBLISHER_SHARDS`, `OBS_BUFFER`, `FRAME_BUFFER`, `RAW_PAYLOAD_MAX_BYTES`, `DLQ_RATE_PER_SEC`, `FEED_STALE_*`, `FEED_RETRY_*`, `LEASE_ENABLED`, `LEASE_TTL_SEC`, `LEASE_TICK_SEC`, `LEASE_REBALANCE_SEC`, `SHUTDOWN_TIMEOUT_SEC`.
- Scaling: `docker compose up -d --scale ingest-service=3`; the Helm chart's `ingestService.replicaCount`. Site receivers should be pulled (`tcpclient`, or `tcp` in connect mode) rather than listened for, so any replica can own them; connections that listen run on the listener replica, which does not scale out.
- Shutdown: readiness turns 503, the supervisor stops every driver and writes stopped status rows, the publisher drains, the producer flushes, leases and the replica row are released, bounded by `SHUTDOWN_TIMEOUT_SEC`.
- Metrics (`/metrics`): `frames_total`, `observations_total`, `decode_errors_total`, `skipped_total`, `duplicates_total`, `feeds_running`, `feed_last_success_timestamp`, `feed_entities_count`, `feed_errors_total`, `feed_restarts_total`, `leases_lost_total`, `lease_handovers_total`, `observations_published_total`, `observations_delivery_failed_total`, `deadletter_total`, `deadletter_dropped_total`, `publisher_shard_depth`, `publisher_blocked_seconds_total`, labelled by `feed_id` and `driver`.
- Kafka: `observations.raw` (24 partitions, 3 days, key = `ICAO24:ABC123` or `feed:<id>:<sourceEntityId>`), `observations.dlq` (3, 30 days). Headers on every message: `content-type`, `schema`, `schema-version`, `producer`, `feed-id`, `x-fence`; dead letters add `driver`, `decoder`, `reason`, `error`, `received-at`.

## Adding a driver

Everything lives under `apps/ingest-service/internal/source`.

1. **Decide the shape.** A new wire format over an existing transport is a decoder; a new way to fetch (an API with its own scheduling or request shaping) is a driver; a new way to move bytes is a transport.
2. **Decoder** (`decoder/<name>/`): implement `decoder.Decoder` (`Decode(transport.Frame) ([]*obs.Observation, error)`, `Close()`), fill the object fields of `obs.Observation` (source entity id, `Source`, entity type, environment, position with `SetPosition`, kinematics with `obs.Float`, identities with `AddIdentity`, a platform block), return `decoder.Skip(reason)` for frames that carry nothing and an error for frames that are broken. Register in `init()` with `decoder.Register(decoder.Definition{Name, Description, Source, ContentType, New})`, add the name to the `decoder.name` enum in `driver/stream/schema.json`, and write table tests on real frames.
3. **Driver** (`driver/<name>/`): embed a `schema.json`, implement `driver.Driver` (`Run(ctx, sink)`, `Health()`), use `httppoll.NewScheduler` and `httppoll.NewClient` for a poller, implement `aoi.AreaAware` when the area of interest shapes requests, and register in `init()` with `driver.Register(driver.Definition{ID, Name, Description, Source, Capabilities, SecretFields, AreaTTL, ConfigSchema, New})`. Emit through the sink (`Emit`, `Succeeded(count)`, `Skipped(reason)`, `DeadLetter`); never touch Kafka or the generated protobuf code.
4. **Transport** (`transport/<kind>/`): implement `transport.Transport` (`Run(ctx, emit)`, `State()`), honour `ErrBackpressure` from the emit, set `Listens` when it binds a port, and register with `transport.Register`.
4b. **Sink or bidirectional driver** (a connection that sends): set `Direction: driver.DirectionOut` (or `DirectionBoth` when it also receives) in the definition and implement `driver.Consumer` beside `driver.Driver`: `HandleEntity(ctx, driver.EntityUpdate)` gets an upsert with the full `sentinel.v1.Entity` snapshot or a removal (`Reason` `deleted`, `aged_out` or `policy`), `HandleAlert(ctx, *sentinelv1.AlertEvent)` gets triggered, acknowledged and resolved alerts. Calls arrive from one goroutine per connection, already filtered by the policy, coalesced and rate-limited; return `driver.ErrNotConnected` while the remote is unreachable so the pump pauses and keeps its queue, any other error counts a delivery failure. `Run` owns the session (and the inbound side for `both`); the supervisor runs the pump beside it and restarts the connection when either stops. Read Sentinel's own geofences and locations through `deps.Shapes` when the remote can show them. The `tak` driver and the `cot` encoder are the reference.
5. **Register the package** with one import line in `source/all/all.go`, add a validation case to `drivers/catalog_test.go`, and a recipe to `docs/development.md`.
6. **Try it live**: create the feed through `POST /api/v1/feeds`, watch `GET /api/v1/feeds/{id}/status` and `/metrics`, and confirm observations on `observations.raw` and nothing unexpected on `observations.dlq`.
